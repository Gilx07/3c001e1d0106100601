DUMMY DLL MinHook v2 — Runtime Instrumentation & Binary Analysis

25 Agustus 2026Windows / MinHook / x86

Overview

DUMMY DLL MinHook v2 merupakan studi reverse engineering terkontrol terhadap sebuah binary Windows x86 untuk memahami bagaimana alur validasi, pembentukan machine identifier, hashing, komunikasi network, response handling, dan keputusan akhir program dapat dipetakan secara statis maupun diamati saat runtime.

Fokus instrumentation adalah model observe/delegate: hook digunakan untuk melihat parameter, hasil fungsi, urutan pemanggilan, dan data yang melewati boundary tertentu, sementara keputusan program tetap dikembalikan dari implementasi original.

Scope: pembahasan ini berfokus pada observability dan struktur program. Detail yang secara langsung dapat digunakan untuk mengubah keputusan validasi tidak dipublikasikan.

Binary dan proses analisis

Target yang dianalisis berbentuk PE32 untuk arsitektur x86 dan pada versi awal menggunakan packing. Setelah proses unpacking, section layout menjadi lebih mudah dipetakan sehingga hubungan antara code section, data, import table, resource, relocation, dan entry point dapat dianalisis dengan lebih konsisten.

Pemisahan antara analisis packed dan unpacked penting karena alamat relatif serta struktur fungsi menjadi jauh lebih stabil setelah lapisan packing tidak lagi mendominasi control flow awal.

High-level activation flow

Pipeline yang teridentifikasi membangun data mesin dari beberapa Windows API, memproses data tersebut menjadi identifier berbentuk hash, menggunakannya pada request network, membaca response, melakukan normalisasi, lalu membandingkan hasil akhir dengan nilai yang diharapkan.

Machine identifier

Tahap pertama mengumpulkan informasi host menggunakan Windows API yang berkaitan dengan volume, computer name, dan system information. Nilai tersebut kemudian digabungkan dalam format tertentu sebelum diteruskan ke helper hashing.

Output pada tahap ini bukan keputusan akhir dan bukan response network. Ia berfungsi sebagai input deterministik untuk membentuk serial yang digunakan pada tahap berikutnya.

Hashing dan serial generation

Binary menggunakan Windows CryptoAPI untuk membuat digest MD5 dari machine data. Digest biner kemudian dikonversi menjadi representasi hexadecimal lowercase sepanjang 32 karakter.

Dari sisi runtime tracing, helper hashing merupakan titik observasi yang berguna karena input machine data dan output serial dapat dibandingkan secara langsung tanpa perlu menebak struktur state yang berada lebih jauh di dalam validation function.

Network request dan WinINet

Komunikasi network menggunakan WinINet. Jalur request memanfaatkan fungsi untuk membuka session, membuka URL, membaca response, dan menutup handle.

Untuk instrumentation, export WinINet merupakan boundary yang lebih stabil daripada memasang hook pada setiap call-site individual. Dengan tracing pada API tersebut, informasi seperti URL request, ukuran read, jumlah byte yang diterima, serta preview data dapat dikorelasikan dengan state aplikasi.

Response handling

Response yang diterima tidak langsung digunakan begitu saja. Binary melakukan terminasi buffer dan normalisasi whitespace sebelum comparison final. Tahap ini menjelaskan mengapa raw response network dan string yang masuk ke comparator dapat memiliki representasi berbeda walaupun secara visual tampak sama.

Membedakan raw response, normalized response, dan final comparison input sangat berguna ketika melakukan debugging karena masalah dapat terjadi pada transport, parsing, normalisasi, atau comparator secara terpisah.

MinHook observation strategy

Strategi yang digunakan lebih mengutamakan hook pada boundary fungsi utuh. Pendekatan ini lebih mudah dipelihara dibandingkan hook pada instruction tengah fungsi dan lebih aman terhadap perubahan kecil pada compiler output.

  • Trace argument yang masuk ke fungsi target.
  • Panggil original trampoline.
  • Catat return value atau output buffer original.
  • Kembalikan hasil original tanpa mengubah keputusan program.
  • Catat call count dan caller context bila diperlukan untuk korelasi runtime.

Pada x86, calling convention harus diverifikasi dengan benar. Prototype detour yang salah dapat merusak stack pointer atau register dan menyebabkan crash yang terlihat seperti masalah pada hook library padahal sumbernya adalah mismatch ABI.

Address validation

Alamat relatif yang ditemukan melalui analisis statis tidak sebaiknya dianggap sebagai satu-satunya sumber kebenaran. Build yang berubah dapat menggeser layout code atau menghasilkan prologue berbeda.

Strategi yang lebih tahan perubahan adalah menggabungkan known relative location dengan validasi signature atau prologue. Jika validasi gagal, pencarian pada code section dapat digunakan untuk menemukan kandidat fungsi yang sesuai sebelum hook dipasang.

Anti-analysis surface

Binary juga memiliki indikator mekanisme anti-analysis. String dan import yang ditemukan menunjukkan adanya perhatian terhadap debugger, process inspection, network inspection, dan beberapa tool reverse engineering yang umum.

Bagian ini perlu diperlakukan sebagai subsystem tersendiri: kapan pemeriksaan berjalan, apa condition yang diuji, serta bagaimana hasil pemeriksaan memengaruhi lifecycle aplikasi perlu dipetakan terpisah dari activation pipeline agar analisis tidak mencampur dua control flow berbeda.

Downloader dan injector subsystem

Selain jalur activation, terdapat subsystem lain yang memiliki karakteristik downloader dan process injection. Import yang berkaitan dengan pembukaan process, alokasi memory pada process lain, penulisan memory, resolusi fungsi, dan pembuatan remote thread menunjukkan bahwa jalur ini berbeda secara konseptual dari validation logic.

Pemisahan subsystem membantu memastikan telemetry activation tidak tercampur dengan activity loader ketika event runtime dianalisis.

Nilai instrumentation

Manfaat utama pendekatan ini bukan sekadar melihat satu return value, tetapi membangun timeline yang dapat menjelaskan hubungan antara input host, serial generation, request network, response bytes, normalisasi, comparator, dan keputusan akhir.

Dengan telemetry seperti itu, analisis dapat dilakukan secara repeatable: satu sesi runtime dapat dibandingkan dengan sesi lain tanpa harus mengandalkan snapshot debugger tunggal atau interpretasi manual dari disassembly.

Penutup

DUMMY DLL MinHook v2 menunjukkan bagaimana analisis statis dan runtime instrumentation dapat digunakan bersama untuk memetakan sebuah binary Windows secara sistematis. Static analysis memberikan struktur dan kandidat boundary, sementara tracing runtime memberikan data nyata mengenai urutan eksekusi dan nilai yang benar-benar melewati fungsi tersebut.

Untuk tahap lanjutan, pendekatan yang paling kuat adalah mempertahankan pemisahan antara validation telemetry, network tracing, anti-analysis mapping, dan loader subsystem sehingga setiap bagian dapat diuji serta diverifikasi secara independen.
